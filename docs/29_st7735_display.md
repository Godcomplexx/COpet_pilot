# Замена дисплея на 1,77″ ST7735/ST7735S

Прошивка теперь рассчитана на предполагаемый контроллер ST7735R/S и
матрицу 128×160 в портретной ориентации. Маркировка платы на фотографии
не подтверждает контроллер: окончательная проверка — запуск на устройстве.
Старый ST7789/GMT130 больше не инициализируется этим драйвером.

## Подключение

Питать и перепаивать при отключённом USB/внешнем питании.

| Контакт модуля | ESP32 |
| --- | --- |
| 1 GND | GND |
| 2 VCC | 3V3 |
| 3 SCK | GPIO18 |
| 4 SDA (SPI MOSI) | GPIO5 |
| 5 RES | GPIO17 |
| 6 RS (DC) | GPIO16 |
| 7 CS | GND |
| 8 LEDA | Питание подсветки согласно схеме модуля, не GPIO |

У аналогичного модуля AZ-Delivery LEDA рассчитан на 3,3 В. Если схема
конкретного экземпляра неизвестна, для первого включения используйте
последовательный резистор 100–220 Ом от 3V3; яркость будет ниже.
Контакты 9–14 не используются. CS постоянно активен, поэтому эта SPI-шина
выделена только дисплею. Для совместной шины нужен отдельный GPIO CS.

## Изображение и настройки

Все существующие экраны рисуются в логический буфер 240×240. При передаче
драйвер уменьшает весь кадр до 128×128 методом ближайшего соседа и переводит
RGB332 в RGB565, старшим байтом вперёд. Это сохраняет расположение элементов
и не обрезает меню, но текст становится мельче, тонкие линии могут исчезать.
Пропорции сохранены: сверху и снизу остаются чёрные полосы по 16 пикселей.
Это совместимость
существующего интерфейса, а не новая вёрстка под родное разрешение.

Настройки: `idf.py menuconfig` → `CoPet Pilot` → `ST7735 1.77-inch display`.

- По умолчанию смещение X=0, Y=0, порядок BGR, инверсия выключена.
  Пользователь подтвердил ровную тестовую сетку на этом профиле 2026-09-16.
- Для другого экземпляра модуля могут потребоваться другие X/Y.
  Начальный профиль X=2, Y=1 на этой плате давал диагональное искажение.
- Если красный и синий перепутаны, переключите `BGR panel color order`.
- Если чёрный стал белым, переключите `Invert panel colors`.
- Если изображение вверх ногами, включите поворот на 180°.

SPI: mode 0, 1 МГц. DMA-буфер 4096 байт, логический буфер 57600 байт.
Частота снижена с 10 МГц 2026-09-16 для проверки искажений на длинных
проводах: на фото видны повторяющиеся скошенные фрагменты и цветной шум.
Это диагностическая проверка, причина искажений пока не подтверждена.
Сборка с 1 МГц записана через COM3 2026-09-16, контрольные суммы проверены.
Журнал после перезапуска подтвердил `SPI mode 0, 1000000 Hz` и `Mode: DESK`.
Пользователь сообщил, что на 1 МГц искажения остались без изменений.
Одно снижение частоты проблему не устранило.
При 1 МГц передача полного кадра занимает не менее 0,328 секунды,
поэтому анимация временно будет заметно медленнее.
Изменения настроек требуют пересборки и прошивки.

### Диагностика без интерфейса

`Show native panel test instead of starting CoPet` в меню дисплея
(`CONFIG_COPET_LCD_DIAGNOSTIC=y`) заменяет обычный запуск отдельным тестом:
красная, зелёная, синяя заливки по три секунды, затем неподвижная картинка.
Верхняя половина картинки — три вертикальные полосы (красная, зелёная,
синяя), нижняя — белая сетка с шагом 16 пикселей на чёрном фоне.
По периметру белая рамка толщиной два пикселя; жёлтый квадрат сверху слева,
пурпурный снизу справа. Порядок красного и синего зависит от настройки BGR.

Тест отправляет готовый RGB565-кадр 128×160 с одним окном адресации;
масштабирование UI и отдельные окна полос не используются. Инициализация
контроллера остаётся прежней. После теста картинка остаётся на экране,
датчики, звук и Wi-Fi не запускаются. Перезапуск повторяет тест.
Для возврата к обычной работе отключить настройку и перепрошить.
Диагностическая сборка записана через COM3 2026-09-16. Сборка и проверка
контрольных сумм прошли; журнал подтвердил завершение RED/GREEN/BLUE/GRID
без тайм-аутов. В локальном `sdkconfig` диагностический режим включён.
Фото первого теста (X=2, Y=1) показало регулярный диагональный сдвиг полос
и сетки даже без масштабирования UI. Следующая диагностическая сборка
записана с X=0, Y=0; остальные настройки сохранены. Контрольные суммы
проверены, журнал подтвердил `offset 0,0` и завершение RED/GREEN/BLUE/GRID.
Пользователь подтвердил: при X=0, Y=0 тест стал ровным. Эти значения
закреплены как настройки по умолчанию в Kconfig. В локальном `sdkconfig`
диагностический режим отключён для возврата обычного интерфейса.
Обычная прошивка с X=0, Y=0 записана через COM3, контрольные суммы
проверены. После перезапуска журнал подтвердил `offset 0,0` и `Mode: DESK`.
Частота SPI пока оставлена 1 МГц. Пользователь подтвердил работу обычного
интерфейса, но заметил вертикальное растяжение. Масштабирование исправлено
на 128×128 с чёрными полями по 16 пикселей. Все 336 host-проверок прошли,
включая проверку пропорций квадрата, чёрных полей и границ полос передачи.
Исправленная сборка записана через COM3; контрольные суммы и запуск
`Mode: DESK` проверены. Визуальное подтверждение новых пропорций ожидается.

## Сборка и проверка

В терминале ESP-IDF 5.5.2, из корня проекта:

```powershell
# Нужны только если отсутствуют сгенерированные звуковые ресурсы:
powershell -File tools/convert_sounds.ps1
powershell -File tools/generate_speech.ps1

powershell -File test/host/run_tests.ps1
idf.py build
idf.py -p COM3 flash monitor
```

COM3 замените портом своей платы. При запуске журнал должен содержать
`ST7735: UI 240x240 -> panel 128x160`. Проверить на железе: загрузочный экран,
лицо, нижние подписи, меню, таймер, цвета и ориентацию. Белая подсветка сама
по себе не подтверждает работу SPI или правильность контроллера.

Проверено 2026-09-15: 335 host-проверок в 12 наборах прошли, включая 13
проверок преобразования дисплея. Полная сборка ESP-IDF 5.5.2 для ESP32
завершилась успешно; `build/copet_hardware_test.bin` занимает 0x1de0f0 байт,
в разделе приложения свободно 38%.

Эта сборка записана на ESP32-D0WD-V3 через COM3 2026-09-15, контрольные суммы
проверены. После перезапуска журнал подтвердил инициализацию ST7735 с
профилем X=2, Y=1 и переход в `Mode: DESK`. Проверка проводилась без
подключения LEDA (контакт 8). Наличие и качество изображения ещё не
подтверждены визуально: успешная отправка SPI-команд не подтверждает
ответ дисплея, поскольку обратное чтение не подключено.

Источники: [модуль AZ-Delivery](https://www.az-delivery.de/en/products/1-77-zoll-spi-tft-display),
[инициализация ST7735 от Adafruit](https://github.com/adafruit/Adafruit-ST7735-Library/blob/master/Adafruit_ST7735.cpp).
